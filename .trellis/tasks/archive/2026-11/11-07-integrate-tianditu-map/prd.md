# 接入天地图地图服务

## 目标

在现有旅行站点中增加天地图组件，同时保留高德组件。业务页面通过直接选择组件决定地图供应商：使用 `TravelMap` 继续使用高德，使用新增的 `TiandituMap` 使用天地图。

## 背景与约束

- 项目是 Vite + React + TypeScript，现有高德封装位于 `src/TravelMap.tsx`。
- 现有组件已支持路线折线、计划点/备选点/普通点标记、弹窗、聚焦、全图适配、缩放、浏览器定位和加载错误状态。
- 现有高德配置为 `VITE_AMAP_KEY`、开发环境安全密钥和生产环境 `_AMapService` 代理，继续保持兼容。
- 天地图开发者平台为 `https://cloudcenter.tianditu.gov.cn`，浏览器端 Key 由业务方申请；真实 Key 不提交仓库。
- 组件选择由业务代码控制，不增加全局环境变量或运行时地图切换按钮。

## 需求

1. 新增独立的 `TiandituMap` React 组件和天地图 SDK 加载/实例适配模块。
2. 复用现有地图点位、行程和筛选数据契约，业务页面可以仅替换组件导入即可选择地图。
3. 天地图组件实现与高德组件一致的核心交互：路线、标记、弹窗、聚焦、全图适配、缩放、浏览器定位、键盘/无障碍操作。
4. 天地图 Key 使用独立的 `VITE_TIANDITU_KEY` 配置；缺少 Key、SDK 加载失败和地图初始化失败必须有明确状态，页面其他内容仍可用。
5. 高德现有页面、配置、生产代理和行为不回归。
6. 更新 `.env.example`、README 和回归测试，记录两套地图的配置与使用方式。

## 已确认决策

- 高德和天地图并存，不迁移、不互相回退。
- 地图配置、SDK 加载器、实例和覆盖物适配分模块维护。
- 不使用 `VITE_MAP_PROVIDER`；业务直接选择 `TravelMap` 或 `TiandituMap`。
- 默认现有页面继续使用高德，天地图通过明确导入 `TiandituMap` 的页面启用。

## 暂不纳入

- 天地图 Web 服务的地理编码、路径规划、POI 搜索和逆地理编码。
- 移动端原生 SDK、小程序 SDK、离线地图和三维地图。
- 页面视觉重做、用户运行时地图切换按钮。

## 验收标准

- 配置 `VITE_TIANDITU_KEY` 后，使用 `TiandituMap` 的页面能加载天地图并展示现有点位。
- 天地图路线、点位、弹窗、聚焦、缩放、定位和键盘操作满足现有 `TravelMap` 交互契约。
- 天地图缺少 Key、SDK 加载失败、初始化失败时显示明确状态，地点列表和外链仍可用。
- 现有使用 `TravelMap` 的旅行页和观星页保持高德地图行为不变。
- `.env.example` 和 README 同时说明 `VITE_AMAP_KEY` 与 `VITE_TIANDITU_KEY`，并写清组件选择方式。
- `npm run lint`、`npm run typecheck`、`npm run build` 和地图回归检查通过。

## 技术未知项

- 天地图 JS API 4.0 的实际类名、事件和 `fitBounds`/定位能力需在实现阶段以官方 SDK 文档和浏览器实测为准；必要时使用原生浏览器定位和手动边界计算保持契约。
