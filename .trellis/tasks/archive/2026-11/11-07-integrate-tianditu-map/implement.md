# 实施计划

1. 阅读 frontend 架构、质量和观星规范，确认共享类型抽取不改变现有旅行数据。
2. 抽取地图共享 props/点位类型，保留 `TravelMap` 的现有导出兼容性。
3. 新增天地图 SDK 加载器和 `TiandituMap` 组件：初始化、路线、标记、信息窗、聚焦、缩放、定位、清理和错误状态。
4. 为天地图补充独立回归页面或 SDK mock，覆盖首次选点、键盘选择、重复点击、单点聚焦和无配置状态。
5. 更新 `.env.example`、README 和必要的页面示例，说明业务通过导入组件选择地图。
6. 检查现有高德页面和 `tests/travel-map-focus.html`，确保高德实现、配置和代理未被改坏。
7. 运行 `npm run lint`、`npm run typecheck`、`npm run build`、`npm audit`，并执行地图回归页面检查。
8. 修复检查发现的问题，完成最终质量检查后再归档任务。

## 风险点

- 天地图 SDK 全局命名空间或事件签名与文档示例不同：先用最小 mock/浏览器加载验证，再扩展覆盖物。
- `MapPlace` 类型抽取导致导入路径变化：保留 `TravelMap` 的类型导出或兼容 re-export。
- 两家地图坐标显示偏差：不改写原始数据，明确记录适配层转换并用已知点位人工检查。

## 回滚点

- 共享类型抽取后先运行高德测试；若失败，恢复兼容导出再继续天地图。
- 天地图组件独立提交范围，失败时可删除该组件和新增配置，不影响高德文件。
