# 广东流星雨与星空拍摄地图

## 目标

新增广东省内流星雨与星空拍摄地点页，供从深圳出发的用户比较距离、暗空条件和夜间天气。执行顺序：方案评审 → 小红书采集与点位核验 → 页面开发 → 验收。

## 已确认背景

- 用户要求通过插件操控 Edge，在小红书使用不少于 10 个关键词，每个关键词搜索不少于 50 篇帖子。
- 现有站点为 React + TypeScript + Vite 静态应用，地图为高德 JS API 2.0。入口见 src/App.tsx:5；旅行注册见 src/trips/index.ts:1。
- README.md 风格库已保存 6 套风格。2026-08-12 会话 019ff615-1d7f-7240-a4f8-de9daeb0ee0d 仅保存备选风格，本页在本任务方案阶段选定 Sketchbook。
- 当前 Trellis 为 inline 模式；用户已批准采集、开发和并行子代理。

## 要求

### R1 采集与证据

- 首批 12 个词见 research/search-plan.md，每词至少 50 个不同帖子 ID，最低 600 条关键词—帖子记录。
- 同词、跨词分别去重统计，不能将 600 条搜索记录说成 600 篇全局独立帖子。
- 保存实际浏览的标题、链接、关键词、采集时间、阅读深度、地点线索和筛选结论。候选地点须进入帖子详情核对，不能只凭标题/封面推荐。
- 不相关、广告、重复、地点不明与无法读取的记录分别标注；搜索不足 50 时记录实际缺口，不以其他词的记录冒充补足。

### R2 点位目录

- 仅收录广东省内地点，合并别名，区分同名地点、山顶与停车场、景区与具体机位。
- 每点包含名称、城市、坐标及精度、拍摄理由、地形/视野、通达条件、夜间开放信息、来源与核验日期。
- 已确认封闭或不可合法进入的机位不进入推荐列表；开放信息有矛盾时明确标注。
- 点位数量以证据决定，不为凑数生成没有来源的地点。

### R3 列表与地图

- 独立地址 /trips/guangdong-stargazing/，首页有入口。
- 桌面列表与地图并排，窄屏上下排布。选择列表聚焦地图；点击标记显示对应详情与高德导航。
- 支持地点/城市搜索，按距离深圳和波尔特等级排序，两项均可切换升降序。
- 方案建议固定深圳市民中心为起点，明确显示“直线距离”；不将直线距离当作驾车里程。
- 未知等级在升降序下都排末尾；相同等级按距离与地点 ID 稳定排序。

### R4 波尔特等级

- Bortle 1–9 级，越小越暗；记录来源、图层/模型年份、核验日期与口径。
- 方案采用天空亮度图层的估算等级，显示“估算”；观测者报告单独标注，不能伪装为统一当晚实测。
- 保留来源给出的等级区间。无可靠来源显示“待核验”，不按距离或热度编造数值。
- 天气与暗空分开展示，不承诺低等级必然能看见银河或流星。

### R5 天气与缓存

- 加载页面只读 IndexedDB，不自动请求天气；缓存为空显示“未获取”。
- 顶部提供“更新全部天气”，每点提供“更新天气”。全部更新覆盖完整目录，不受当前筛选限制。
- 展示未来 7 个夜晚的逐小时总云量、低/中/高云量、降水概率、气温、湿度、风速和能见度，使用北京时间。
- 默认今晚；查看窗口为当日 18:00 至次日 06:00，完整覆盖跨午夜时段。窗口不等同于天文黑夜。
- 保存每点最近一次成功预报、获取时间与覆盖时段。超过 6 小时提示缓存较旧，不自动更新。
- 请求中、部分成功、失败、超出预报范围和存储失败有可读状态；失败不覆盖旧的成功数据。
- IndexedDB 不可用时本次天气仍可显示，明确提示未持久保存。
- 按地点跟踪尚未保存的天气；后续批次写入成功不能清掉前批的存储失败提示。对应地点重试写入成功后才解除其未保存状态。

### R6 样式

- 已确认使用 README.md 风格库中的 Sketchbook / Hand-drawn：米白纸感、墨绿、手绘细线、便签式卡片。
- 地图原色清晰，数值与正文易读，普通控件复用已有 shadcn 源码组件。

## 范围外

不做实时轮询、账号、服务端点位数据库、常驻爬虫、付费订阅、驾车路线规划或流星雨事件预测。天气按钮不重新采集小红书；点位目录随项目数据更新发布。
